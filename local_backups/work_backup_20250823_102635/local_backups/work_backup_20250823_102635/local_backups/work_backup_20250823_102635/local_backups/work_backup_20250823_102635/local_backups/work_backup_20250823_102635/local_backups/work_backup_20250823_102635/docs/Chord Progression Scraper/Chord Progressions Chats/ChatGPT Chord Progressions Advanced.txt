pythonimport re
from typing import List, Dict

class HUVEncoder:
    """Encodes chord symbols into Harmonic Usage Vectors (HUV)."""
    
    # Interval mapping (index to label)
    INTERVAL_MAP = {
        5: "b7", 6: "7", 7: "sus4", 8: "sus2", 9: "9",
        10: "b9", 11: "#9", 12: "11", 13: "#11", 14: "13",
        15: "b13", 16: "alt", 17: "no3", 18: "no5", 19: "6",
        20: "b2", 21: "bb3", 22: "#4", 23: "b6", 24: "bb7"
    }
    
    # Implication rules
    IMPLICATIONS = {
        "7": ["b7"],
        "9": ["b7", "9"],
        "11": ["b7", "9", "11"],
        "13": ["b7", "9", "11", "13"],
        "maj7": ["7"],
        "maj9": ["7", "9"],
        "6/9": ["6", "9"],
        "7#9": ["b7", "#9"],
        "7b9": ["b7", "b9"],
        "7b13": ["b7", "b13"],
        "alt": ["b7", "alt"],
        "sus4": ["sus4", "no3"],
        "sus2": ["sus2", "no3"],
        "5": ["no3"],
    }
    
    def __init__(self):
        self.core_counts = [0, 0, 0, 0, 0]  # total, root, 1st, 2nd, 3rd
        self.extensions = {label: 0 for label in self.INTERVAL_MAP.values()}
    
    def encode(self, chord_symbol: str, total: int = 0, root: int = 0, first: int = 0,
               second: int = 0, third: int = 0) -> str:
        """Convert chord symbol to HUV string with counts."""
        self.core_counts = [total, root, first, second, third]
        self.extensions = {label: 0 for label in self.INTERVAL_MAP.values()}
        
        # Parse chord symbol
        symbol = chord_symbol.replace("C", "")  # Normalize (remove root note)
        symbol = re.sub(r"[#b]\d+", lambda m: m.group(0).lower(), symbol)  # Normalize flats/sharps
        
        # Apply implication rules
        for key, implied in self.IMPLICATIONS.items():
            if key in symbol:
                for interval in implied:
                    self.extensions[interval] = 1
                break
        
        # Special handling for 'alt' chords
        if "alt" in symbol:
            for ext in ["b9", "#9", "#11", "b13"]:
                if ext in symbol:
                    self.extensions[ext] = 1
        
        # Build vector
        vector = self.core_counts[:]
        last_non_zero = 5
        for idx in range(5, 25):
            label = self.INTERVAL_MAP[idx]
            vector.append(self.extensions[label])
            if self.extensions[label] > 0:
                last_non_zero = idx
        
        # Early stopping
        return ",".join(map(str, vector[:last_non_zero + 1]))

# Example usage
if __name__ == "__main__":

So every row can be mapped automatically to the correct catalog bin in the necklace doc.
2. Integration Workflow
Parse songs with HUV encoder
Every chord in every song → HUV vector.
Extract 4-chord windows
For every consecutive 4-chord slice, normalize to Roman numerals in the detected key.
Check vocabulary constraint
Only accept slices where all chords are from {I, V, vi, IV} (+ extensions allowed).
Classify into catalog
Rotation ID → necklace family.
Inversion features (HUV positions 1–4) → root / 1st / 2nd / 3rd.
Extension flags (HUV positions 5–24) → triads / 7ths / extensions.
If multiple inversion types OR multiple extensions → “Mixed (Complexity Index)” bin.
Populate the catalog automatically
Append the song metadata (title, artist, year, etc.) into the right docx/CSV bin.
3. Benefits
Mathematical completeness: Every possible I–V–vi–IV family is covered, no duplicates.
Direct link between raw data (HUV) and pedagogy (necklace bins): Students see the exact same classification you use in backend analytics.
Scalability: Your 680k dataset (plus scrapes from Hooktheory, Music21, forums, academic corpora, etc.) can all be funneled into the exact same 240-bin framework automatically.
Rich analysis: Because the HUV captures counts, you can even build a complexity index metric (e.g., weighting multiple inversions + extensions) to prioritize which songs go in “Mixed.”
